# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Context

FlowSync is a course exercise repo (LIDR AI4Devs, cohort 202610-ro). It is a TypeScript monorepo with two independent npm projects: `backend/` (AdonisJS 7 API) and `frontend/` (React 19 + Vite). Docs and course material (`README.md`, `prompts.md`) are in Spanish.

For the current exercise the **backend already exists and is not meant to be modified** — work happens in `frontend/`. Read the backend (especially validators) to learn what the API actually requires; the product tickets don't always specify every field.

Requires Node.js 24+ (Node 20 fails with `Unknown file extension ".ts"`).

## Commands

From the repo root (macOS, Linux, WSL): `make setup` (idempotent: installs both projects, creates `backend/.env`, generates `APP_KEY` if empty, runs migrations) and `make start` (runs both dev servers; Ctrl-C or either one dying stops both).

Backend (`cd backend`), served at http://localhost:3333:

```bash
npm install
cp .env.example .env && node ace generate:key   # first time only
node ace migration:run                           # SQLite at backend/tmp/db.sqlite3; also regenerates database/schema.ts
npm run dev          # node ace serve --hmr
npm test             # node ace test (Japa)
node ace test unit   # single suite (unit | functional)
node ace test --files tests/functional/foo.spec.ts   # single file
node ace test --tests "test title"                   # single test by title
npm run lint         # eslint
npm run typecheck    # tsc --noEmit
npm run format       # prettier (@adonisjs/prettier-config)
```

Frontend (`cd frontend`), served at http://localhost:5173:

```bash
npm install
npm run dev
npm run build        # tsc -b && vite build
npm run lint         # oxlint
npm run format       # prettier --write . (format:check to verify)
```

The frontend has no test runner yet. Prettier config: `frontend/.prettierrc.json` (no semicolons, single quotes). A `PostToolUse` hook (`.claude/settings.json` → `.claude/hooks/format-frontend.sh`) runs Prettier on any file under `frontend/` after Edit/Write.

## Backend architecture

Request flow: `start/routes.ts` → controller (`app/controllers`) → VineJS validator (`app/validators`) → Lucid model (`app/models`) → transformer (`app/transformers`) → `ctx.serialize()`.

- **API surface** (all under `/api/v1`):
    - `POST auth/signup` — body `{ fullName (nullable), email, password, passwordConfirmation }`. Password 8–32 chars, `passwordConfirmation` must match, email must be unique.
    - `POST auth/login` — body `{ email, password }`.
    - `GET account/profile`, `POST account/logout` — require `Authorization: Bearer <token>`.
    - Both signup and login return `{ data: { user, token } }`. Tokens are opaque access tokens prefixed `oat_`.
- **Response envelope**: `providers/api_provider.ts` adds `ctx.serialize()`, which wraps every payload in `{ data: ... }`. Controllers return via `serialize(...)`, not raw objects. Validation errors (422) and auth errors come from the default exception handler in AdonisJS's JSON format (`{ errors: [{ message, field, rule }] }`).
- **Auth**: default guard is `api` (`tokensGuard` over `User.accessTokens`, `config/auth.ts`). A session guard (`web`) exists but isn't used by routes. `middleware.auth()` protects the `account` group.
- `force_json_response_middleware` forces `Accept: application/json` on every request. CORS allows any origin in dev (`config/cors.ts`).
- **Transformers** decide what leaves the server — `UserTransformer` picks `id, fullName, email, createdAt, updatedAt, initials` (never the password hash).
- **Schema**: never edit tables by hand; add a new file in `database/migrations/`. `database/schema.ts` is generated from migrations (DO NOT EDIT); models extend those generated schema classes (e.g. `User extends compose(UserSchema, withAuthFinder(hash))`).
- **Generated code**: `.adonisjs/` (controller index used as `controllers.X` in routes, Tuyau client registry, route types) is generated by `adonisrc.ts` hooks — don't edit it by hand.
- Imports use subpath aliases from `package.json` (`#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, etc.) with `.js`-mapped paths.
- Tests: Japa suites `unit` (`tests/unit/**/*.spec.ts`) and `functional` (`tests/functional/**/*.spec.ts`, starts the HTTP server); no test files exist yet. `.env.test` uses `SESSION_DRIVER=memory`.

## Reglas de proceso

- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca
  commitear directo en `main`/`s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción
  completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él, antes de
  darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo
  con la URL del PR.
